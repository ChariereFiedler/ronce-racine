# Mod ronce 0.6: act on what the telemetry and the transcripts show

## Intent

Cut token spend, lengthen the useful part of a session, and lower the number
of fixes per feature, using the ronce mod as the single place where the
guardrails live. The mod is already enabled for every session (user scope),
but the installed copy is 0.1.0 while the source is 0.5.2: none of the work
since 0.1 reaches a session today.

## What the data says

Telemetry (166 sessions with tool calls, 272 with a cost, 2026-10-08 to 11-18):

- 15 942 $ in total; the 10 most expensive sessions are 59 % of it.
- The longest sessions run 500 to 1135 turns and reach 90 to 97 % of the
  context window. Median context is 34 %; 42 % of turns are above 40 %, 23 %
  above 60 %, 11 % above 75 %.
- Shadow rules that never became enforcing: `commit-confirmation` (604 hits),
  `cargo-test-threads` (202), `rm-untracked` (120), `ticket-without-blocked` (30).
- `rodz-iac` alone is 5 294 $, a third of the spend, and was not in the first
  transcript analysis.

Transcripts of granit-golem, ardente-forge, bourgeon and noireaiguille:

- Cost is the context re-read on every turn, not tool output. 22 to 53 % of the
  volume is re-read at more than 500k tokens.
- About 40 to 50 % of fix commits sit in CI and e2e (granit) or have no ticket
  reference (ardente: 512 of 625). One granit ticket produced 91 fix commits.

## Goals

1. A session that grows past a threshold is told so, once per threshold, with
   the handoff to do.
2. A `fix(...)` commit carries a ticket reference.
3. A third fix on the same ticket or scope in a short window is flagged with the
   root-cause skill to use, before a fourth patch is written.
4. A `sleep` used to wait is flagged with the better tool (Monitor).
5. The installed mod is the current source, from a source that does not move.

## Non-goals and anti-goals

- No rule blocks on spend or context size. Cost control stays an alert
  (ardente-forge ADR-0010). A signal that ends a working session is a failure
  even if it saves tokens.
- No hook copied into repositories: hooks stay in the mod, policy in
  `.claude/ronce.json` (docs/distribution-model.md).
- Shadow rules owned by a project's `ronce.json` are listed, not promoted: that
  is each project's decision. `commit-confirmation` in particular would double
  the user's own confirmation.

## Approaches considered

1. **Mod only (chosen).** New default rules and one new turn-level feature in
   `mods/ronce`. One channel, already global, measured by the same telemetry.
2. Command hooks installed per repository. Rejected: the mod replaced them on
   purpose (3 380 ms vs 142 ms per probe) and they drift per repository.
3. Prompt-level guidance only (CLAUDE.md, skills). Rejected as the sole lever:
   the telemetry shows rules that act (2 101 rewrites, 1 367 denied reads) while
   advice does not leave a trace.

## Design (my calls, to be corrected)

- **Context signal.** In `flush()`, compare `usage.context.percent` with
  `features.contextSignal.thresholds` (default `[40, 60, 75]`). When a
  threshold is crossed for the first time in the session, add a one-line
  context message: percent reached, advice to write the state to a file or a
  ticket and continue from a fresh session. Crossed thresholds are kept in
  session state so the message is never repeated. The first two are
  `info`; the last one is stronger in wording but still never a deny.
  Thresholds come from the telemetry above: 25 % would fire on 64 % of turns.
- **Default rules** in `defaults.ts`, each with `examples`:
  - `fix-needs-ticket`: `git commit` whose message starts with `fix(...)` and
    holds no `#<n>` or `T-<id>`; action `warn`.
  - `sleep-poll`: `sleep <n>` as a wait in a command; action `warn`, message
    points to Monitor. A `sleep` under a few seconds in a script stays quiet.
- **Fix-repeat check** as a new builtin `fix-repeat`: on `git commit` of a
  `fix(...)`, read the recent history and count fixes naming the same ticket or
  the same scope within the window (default 3 in 48 h); on match, `warn` with
  the `recurring-bug-root-cause` skill. Unreadable history means no warning.
- **Deployment.** Release 0.6.0, update the installed plugin from the current
  source, point the marketplace at a stable checkout, fix the memory that says
  the mod is read live, add a `ronce.json` to this repository.

## Left to the builder

Exact wording of the messages; the config shape for `contextSignal` (types in
`mods/ronce/types/index.d.ts`); whether `fix-repeat` reads `git log` or the
ticket references in telemetry; the stable marketplace location.

## Verification

Rule examples (`match`/`pass`) run by the policy loader; unit tests for the
threshold crossing and the fix counting; `npm test`; then a probe session after
restart (`claude` loads the mod only at process start).
